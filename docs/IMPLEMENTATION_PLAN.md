## 顺序与依赖

主线：S0 契约 → S1 语义修复 → S2 多任务 → S3 提醒 → S4 角色界面 → S5 桌面控制 → S6 可靠性 → S7 完整验收。

S0 后可并行准备角色素材和原生故障／性能基线；S4 的角色素材与 S6 的原生实现可分开开发。合并前必须统一偏好、可见性、命中范围及提醒身份，避免两端各自维护事实。每一步形成可审查、可单独回归的变更；不要求将整阶段合成一个大提交。

## S0：明确数据、偏好和验证基线

覆盖：R01–R07、R11–R16 的公共约束。

- [ ] 记录当前 SVG 版的空闲、运行、拖动、收起资源占用与操作表现；同机后续对照，包含 WebContent 等关联进程，不先给性能百分比承诺。
- [x] 建立事实／提醒／表现的边界：会话与本轮事件身份、待处理交互、明确结束原因属于事实；提醒确认属于按事件记录；摸头、庆祝进度和睡觉属于本地表现。
- [x] 为同一会话不同轮次建立稳定且仅驻内存的提醒身份；不能只用 `sessionId` 或会因改名变化的 `updatedAt` 去重。旧导航确认、延迟响应和旧定时器不能清除新一轮提醒。
- [x] 设计等待类型的未知回退及真实开始时间的未知状态。客户端 pending 补正不能保证分类，缺少事实时显示通用等待；运行时长不能用快照更新时间代替。
- [x] 定义新增偏好白名单、默认值及迁移：旧 `quiet:true` 保持安静，旧 `false` 保持原提醒行为，保留尺寸／动效／显示设置。暂静用到期时间保存，重启按剩余时间恢复，过期立即恢复所选提醒级别；不记录任务数据。
- [x] 定义扩展字段、动作及错误结果。保持现有认证、同源与输入校验；新增 UI 动作只允许当前已知目标，不能接受任意命令或 URL。
- [x] 实现接口时同步 `docs/PROTOCOL.md`、两端与测试；评估是否升级 HTTP 状态版本及 Native 握手，不提前把草案当成现行协议。

主要入口：`lib/state.js`、`dsh-adapter.js`、`dsh-route.js`、`bridge-server.js`、`preferences.js`、`companion/web/app.js`、`companion/macos/main.swift`。

完成条件：数据来源、身份、默认值、迁移和错误路径清楚；有并发两会话、同会话连续两轮、重连及旧偏好的验收案例。

## S1：先修正任务与提醒语义

覆盖：R01、R02、R03。依赖 S0。

- [x] 气泡同时展示任务标题与状态，创建时保存目标和提醒身份；点击不再重新挑选最高优先级任务。
- [x] 目标已不存在时显示可恢复提示，不静默跳到另一任务；“返回刚才聊天”继续独立工作。
- [x] 完成只作揖一次，再保留安静姿势／待查看标记；轮询、改名、切换面板、尺寸变化和重连不重复庆祝。
- [x] 增加按事件收起完成提醒的方式；通过宠物导航成功只确认对应完成提醒。直接在 DSH 选中时使用可靠的选中事实消退标记，不宣称完整阅读；已在前台的情况需用明确提醒操作兜底。
- [x] 避免现有 `acknowledge(sessionId)` 将所有 outcome 一并清空；明确错误事实不能因导航消失，pending 不能被本地动作解除。
- [x] 将业务状态与摸头等短动作解耦，等待／问题状态条和导航入口不受动作覆盖。

验证：相关状态、适配、桥接、导航测试；新增并发切换后点旧气泡、旧确认晚到、同会话新一轮完成、明确错误导航、完成与摸头交错的行为用例。

完成条件：显示内容与打开目标一致，真实结果不被本地提醒操作改写，每轮只庆祝一次。

## S6：补齐可靠性、节能和诊断

覆盖：R13、R14、R15。契约依赖 S0；集成在 S5 后完成。

- [x] 分别报告进程启动、窗口可见及页面／角色就绪，不把窗口可见当作角色已正常渲染。
- [x] 页面加载失败、角色素材失败及 WebKit 内容进程终止有有限次数恢复与可见错误；素材失败可展示内置 SVG 备用形象，整个页面失效由原生恢复入口兜底，禁止无限重启。
- [x] 隐藏／休眠时暂停画面动画与不必要指针轮询；拖动时保持原生松手兜底，静止时减少调度。父进程与健康监控继续有效。
- [x] 对位置保存、边界回传去重或防抖；相同尺寸／边界不重复发送，不让节能破坏点击穿透。
- [x] 提供用户主动触发的一键诊断预览／复制，仅白名单版本、平台架构、协议、连接／渲染／快捷键状态和脱敏错误码；不复制原始 stderr、URL、路径、标题、会话标识或凭证。

验证：加载失败、资源失败、内容进程终止、重试耗尽、断连、收起唤回、休眠唤醒、宿主退出／停用清理；敏感测试哨兵不得出现在诊断中。同机复测 S0 性能场景，记录测量环境和限制。

完成条件：故障可被发现与恢复，隐藏后无无意义的持续渲染，诊断输出严格最小化；未测量前不声明能耗改善幅度。

## 后续阶段：3D 原型与路线选择

开始条件：当前阶段完成验收。此处为后续计划，不纳入本阶段完成清单。

1. 确认保留阿财特征的角色风格（手办风为候选），先做空闲、拨算盘和摸头三个动作。
2. 用同一角色分别评估透明预渲染和轻量实时 3D；窗口、任务事实、提醒及导航复用，不以更换引擎重写宿主适配。
3. 在真实原生窗口中验证透明合成、命中范围、低动效、隐藏暂停、渲染故障与 SVG 备用；浏览器表现不代替桌面结论。
4. 同机对比当前 2D 基线的 CPU、GPU、内存、帧时间、启动与能耗，并单列 macOS 13／Intel／Apple Silicon；选择路线后再确定素材及实现预算。

养成、换装、番茄钟、商城和跨平台等仍按产品文档列为暂缓候选，不因 3D 原型自动开始。
